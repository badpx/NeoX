# ADR 0003：两后端共享同一份 CPU 覆盖率光栅化

- 状态：已接受（2026-10-24）
- 背景：GL 后端最初按教科书实现 stencil-then-cover + 4×4 超采样盒滤波 AA。
  实测发现：多边缘叠乘场景（半透明边缘上再叠半透明形状）下，任何独立的
  子像素覆盖率算法与 Soft 后端的差异都会超过规范 §9 的边界容差
  （4×4 超采样实测最大 56/255，容差 32/255）。
- 决定：路径覆盖率计算从 soft.c 移出为共享模块 `src/geom.c`，两后端使用
  同一份光栅化结果；GL 后端将覆盖率作为 R32F 纹理上传，GPU 只负责混合与
  合成。§9 修订记录同步更正：跨后端一致性需要的是共享**覆盖率计算**，
  而非共享采样网格。
- 后果：跨后端一致性实测达到逐位一致（比容差条款更强）。代价：GL 后端的
  路径填充性能让位于正确性（CPU 光栅 + 纹理上传），其"链路验证"定位不变。
  未来 GLES3/WebGL2 后端若要独立计算覆盖率（GPU 超采样），须先将 §9 升级
  为"覆盖率容差的可组合模型"——这是已知的规范演进点。
