# ADR 0008：显式选择 GL GPU 输出与目标快照

- 状态：已实现，macOS 实际 GL 验收；Linux 驱动运行验收待完成。
- 问题：参考 GL 执行器为逐位量化一致，每帧上传浮点基底、读回浮点结果、CPU 编码后再次上传。非清屏帧开始时还会读回原目标。
- 决定：设备创建参数 `output_mode` 提供 REFERENCE（默认）与 GPU 两种选择。GPU 模式在 frame_begin 将目标解码到私有 GPU 快照，或直接清除私有快照；执行阶段从该快照装载基底，最后在 GPU 上解除预乘、sRGB 编码并 roundEven 量化。输入源仍在 CPU 转为参考浮点采样格式，因此本次并未改变纹理插值规则。
- 资源契约：快照由后端拥有，公共帧/提交只携带不透明数据与释放回调；录制取消、失败、排队销毁和提交完成都归还快照。frame_begin 的快照时点不因更早排队帧稍后执行而改变。
- 精度：GPU 编码/目标解码允许末位差异，必须显式选择，执行报告标记 USED_APPROXIMATION。参考模式的精确断言保持原样；新增 GPU 模式对所有既有一致性场景增加全图每通道 ≤1 码值断言，并保留边界和单调性检查。该结果不是任意输入/驱动的误差定理。
- 成本：`neox_gl_device_get_stats` 累计统计像素上传/回读载荷、顶点载荷、读回调用、glFinish 次数、已知纹理存储和所属 context 的分配峰值。统一内存硬件上的 API 拷贝载荷不等于物理总线流量；纹理存储不含驱动开销。GL 仍同步完成，未将 CPU/GPU 全部重叠。

## 验收场景与一次测量

`test_gl_output`：256×64 的 RGBA 渐变/透明纹理，预热后 40 帧交替清屏与保留目标内容；测量窗口内不截图。还检查取消不写目标、排队帧持有原目标快照、分配失败取消和销毁时回收。

在 macOS、本机 GL、Debug + ASan/UBSan 下的一次运行：

| 指标（40 帧，时间为每帧） | REFERENCE | GPU |
|---|---:|---:|
| 像素上传载荷 | 13,107,200 B | 0 B |
| 像素回读载荷 | 11,796,480 B | 0 B |
| 回读调用 | 60 | 0 |
| glFinish | 40 | 40 |
| context 分配峰值（含前置测试） | 958,480 B | 110,608 B |
| 已知 GPU 纹理存储（含池保留项） | 851,968 B | 1,114,112 B |
| CPU 墙钟时间 | 2.724 ms | 0.491 ms |

本次输出像素差为 0。计数由测试断言，时间仅作观测，不设脆弱的速度阈值。
GPU 私有快照增加了保留的 GPU 存储，不应把 CPU 峰值降低描述成总内存必然降低。
上述零上传仅适用于已驻留纹理场景；路径和裁剪仍会上传 CPU 掩码。

## 后续

参考 GPU 纹理仍为 RGBA32F；覆盖率和裁剪仍使用 CPU 结果。GL fence 异步、Metal 同类 GPU 输出路径、真正的独立 GPU 覆盖率算法分别评估，不由本次测试冒充完成。
