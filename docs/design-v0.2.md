# NeoX 设计方案 v0.2

> 本文是 NeoX 的总体设计文档，经一轮完整方案评审修订而成。语义细节以
> [semantics-v0.md](semantics-v0.md) 为准；重大决策的取舍过程见 [adr/](adr/)。

## 1. 定位

NeoX 是一个 2D 图形库：**矢量路径、位图、文字、图层合成与滤镜**。
NeoSDK 的精神续作，不继承其接口。

**非目标**：通用 3D 场景图与材质系统；UI 组件库；音频/视频编解码（未来以
独立模块存在）；应用框架级响应式/DataBinding 系统（仅在其下方提供属性变更
与失效通知机制）。

设计中心是**图形描述与前后端之间的契约**，以及这些契约在资源受限环境、
异构 GPU 环境和可测试性要求下的成立条件。所有性能与能力陈述均为待验证的
假设，不是承诺。

## 2. 三个独立契约

| 契约 | 职责 | 形态 | 稳定性策略 |
|---|---|---|---|
| **SD（语义描述）** | 画什么、如何组合、结果必须满足的规则 | 平台无关数据结构 + 语义规范文档 | 最先稳定；双实现验证后才冻结 |
| **ER（执行表示）** | 面向当前设备的批次、工作缓冲、同步 | 各后端私有 | 永不稳定，随时可重写 |
| **CAP（捕获/传输）** | 录制内容的持久化与跨边界传输 | 带版本的二进制格式 | 早期显式版本号，允许不兼容升级 |

推论：正常本地绘制路径不经过序列化；不预先冻结完整 schema，第一阶段只
冻结"已被两个实现验证的最小子集"。

## 3. 录制、保留、增量：三个分开的能力

立即式 API 与保留场景树是同一执行系统的两种生产方式：

1. **录制**：绘制操作可保存与重放（CAP 契约）；
2. **保留**：内容有稳定身份，可定点修改；
3. **增量执行**：变更后只重做必要工作。

立即式 API 的成本目标（可测量）：立即路径不强制创建持久节点（每帧持久
节点净增为 0）；不承担 diff 与依赖维护（可在立即-only 构建中裁掉）；
命令构建、资源引用、提交验证的真实开销纳入基准测试。

## 4. 资源模型与句柄契约

句柄（index + generation）只是访问方式，安全来自四条显式契约：

1. **归属**：句柄绑定 {实例, 设备, 资源类型}，跨域使用为契约错误；
2. **所有权**：唯一 owner + 借用标记，API 对每个参数标注所有权转移语义；
3. **提交后存活期**：资源从提交到设备完成使用之间不得释放，延迟回收队列
   由后端同步原语驱动；
4. **CAP 映射**：捕获文件中的资源 ID 经显式映射表转换为本地句柄，不假设
   两端槽位一致。

资源对象真实拥有像素数据；`load`（磁盘→像素）与 `upload`（像素→设备资源）
是两个显式阶段，各自可失败、可测量。解码不属于核心。

## 5. 执行后端：算法 × 设备 API 二维矩阵

| | Metal | Vulkan | WebGPU | GLES3/WebGL2 | 无 GPU |
|---|---|---|---|---|---|
| 扫描线（CPU） | — | — | — | — | Soft |
| 三角形批渲染 | ✓ | ✓ | ✓ | ✓ | — |
| Compute 管线 | ✓ | ✓ | ✓ | — | — |

- 同一后端内部允许混合算法；算法选择是后端内部细节，不进 SD 契约。
- "Compute 减少 CPU 几何工作"不等于总成本更低；算法选型必须由固定场景
  基准驱动（CPU/GPU 时间、内存、传输量、功耗），不设全局默认结论。
- Soft 后端职责：嵌入式支持、CI 参照之一、算法试验场；**不是唯一正确性
  标准**（可能与 GPU 后端共享同源错误，且无法验证 GPU 生命周期与同步）。
- 平台胶水层的成本（表面获取、图像导入、格式转换、同步、呈现调度）被显式
  承认；性能分析覆盖从 SD 提交到像素呈现的整条路径。

## 6. 能力协商与失败语义

- **默认保持语义，无法满足即明确失败**，不静默近似；
- 降级是显式 opt-in，且实际执行路径可在正式构建中查询（`neox_exec_report`）；
- 能力位表达"能否以全语义执行"，不是"能否给出某种输出"；
- 原生互操作是完整契约：所有权、格式、访问状态、同步条件、影响范围，
  超越裸句柄导出。

## 7. Shader 与工具链

- 核心运行时不携带通用着色器编译器；允许离线完成的工作尽量离线完成；
- 运行时编译停顿通过预热、异步管线创建、磁盘缓存压制；
- 内置效果以有限、枚举、离线准备好的管线提供；自定义 shader 经构建期
  工具链接入。

## 8. 文字管线

- 核心只接受已定位字形（glyph id + 位置 + 图集引用）；字体解析、shaping、
  回退、布局在独立的 NeoX-Text 模块；
- MSDF / 位图图集 / CPU 光栅化轮廓是并列可选的字形绘制表示；
- 固定内容可离线烘焙；动态文字需要运行时光栅化，该依赖不进核心。

## 9. 内存与线程：可测试的约束

1. 核心可在无系统堆、无后台线程环境编译运行（裸机构建证明）；
2. 内存容量可固定：注入分配器，容量、耗尽行为、回收规则全部文档化；
3. 更新失败不留半完成状态；
4. 设备完成使用前，相关内存不被复用（延迟回收队列）；
5. 串行配置只保留必要的调度机制——"单线程"不等于"同步"（GPU/DMA 仍异步）；
6. 所有分配点有明确的失败传播路径，纳入内存耗尽测试。

**依赖策略**：vendor 第三方代码降低安装难度，但不消除审计、维护、升级
责任；不为统一风格大规模改写上游代码。依赖按"核心必需 / 模块必需（可裁剪）/
仅工具链"三级分类，核心级依赖目标数量为零。

**预处理器立场**：不用预处理器表达平台能力的语义差异（那是能力位与链接
选择的职责）；适配文件内部的工具链差异、SIMD 分支等条件编译是正当的。
所有条件编译组合有 CI 覆盖或显式标记为不支持。

## 10. 验证体系

**语义一致性**：立即式与保留式一致；增量更新与完整重绘一致；分块与整幅
一致；缓存开关语义不变；Soft 与 GPU 后端在 §9 容差内一致。

**鲁棒性**：内存耗尽注入；资源失效后可继续运行；GPU 专项（同步、设备丢失
恢复、原生资源互操作）。

**确定性回放的完整条件**：输入事件数据化 + 时间源注入 + 随机源注入 +
资源版本记录 + 外部数据快照。

## 11. 平台矩阵

| 目标 | 路径 | 未自动获得的部分 |
|---|---|---|
| 桌面 | 原生编译 + GPU/Soft 后端 | — |
| 移动 | 原生编译；Metal/GLES | 表面生命周期、内存压力下资源驱逐 |
| 浏览器 | WASM 编译目标 + WebGPU/WebGL2 后端 + JS 胶水 | WGSL 运行时编译、线性内存与分配器衔接、呈现调度 |
| Node.js | WASM(WASI) 或 N-API addon | 数据传递、资源加载、异步调度、打包 |
| 裸机/RTOS | freestanding + Soft + 帧缓冲胶水 | 具体芯片 DMA/显存逐个适配 |

## 12. 开放问题

- SD 节点粒度（粗/细）——待原型数据支撑；
- 色彩管理作用域（全链路线性 vs 输出端转换）——Soft 性能预算相关；
- CAP 是否承担远程渲染协议职责；
- 滤镜图表达上限（固定效果集 vs 可组合 DAG）与"无运行时编译"的张力。
