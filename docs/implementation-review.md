## 1. 资源与提交生命周期

已实施：

- 槽位初始化、回收、generation 由公共表管理；回收不分配内存，generation 耗尽时退役槽位。
- 设备身份跨 context 唯一且不重复分配；GPU 缓存同时校验资源代际和内容版本，Metal 内容变化使用新纹理对象，避免覆写旧在途读取。
- 命令录制即持有资源引用，所有权随命令移交到提交；公开句柄释放不影响已录制内容。
- 异步提交区分未启动和在途，execute 只执行一次；wait 返回执行错误。
- 增加 neox_submission_release：立即撤销报告句柄，在途工作完成后由 pump 回收。调用方应释放每个返回的提交；窗口循环已采用。
- 销毁取消尚未启动的提交，等待已经提交的 GPU 工作，最后销毁资源。修复 Metal 在途销毁循环与初始化失败泄漏。
- 修复 Metal scissor 负数转无符号，先与目标求交。

身份设计的取舍：64 位不透明句柄分为设备 24 位、类型 4 位、代际 16 位、索引 20 位。宿主构建使用一个原子设备身份计数器，它不保存资源，也不参与渲染语义。计数耗尽明确失败而不回绕。NEOX_SINGLE_THREADED=ON 去除原子操作，要求整个进程串行创建设备，不要求线程运行库。CAP 从不序列化这些进程内身份。该身份元数据是对早期“无全局可变状态”描述的明确、有限例外。

验收：新增 tests/test_runtime.c，检查跨 context/资源复用、录制期释放、慢异步重复 pump、pending release、错误传播、代际耗尽、销毁取消及 1,000 帧释放后内存不增长；自定义分配器检查释放尺寸并要求最后零存活字节。新增 tests/test_gpu_runtime.c，检查 GL/Metal 红纹理释放后复用为不同尺寸蓝纹理、pending 释放后销毁。GPU 不可用返回 CTest SKIP，设置 NEOX_REQUIRE_GL/NEOX_REQUIRE_METAL 时必须实际执行。

## 字体缓存身份与归属

- 字体使用文本上下文内单调、耗尽时明确失败的 64 位 ID；图集缓存只保存 ID，不保留已销毁字体对象的地址。销毁字体再复用同一地址，不会误命中旧字形。
- 布局/字体/图集必须属于同一文本上下文，图集设备必须属于该文本上下文的核心 context，绘制帧必须属于图集设备；拒绝发生在缓存查询与写入之前。
- layout 继续按公开 API 借用字体，须先于字体和文本上下文销毁；图集不借用字体对象，但须先于设备销毁。v0 图集无驱逐，销毁字体不会回收已占用的图集空间，空间随图集销毁释放。

## 矩阵组合与距离场缩放数值边界

- 公共 PUSH 发射边界拒绝组合后非有限矩阵及无法表示的平均缩放，三种前端
  一致拒绝且不发布半条命令；场景/CAP 仍按整体事务回滚。
- 距离场平均奇异值改用 `(s0+s1)^2 = ||M||_F^2 + 2|det(M)|`，以 double
  做中间计算，避免原 float 四次项溢出和特征值相减产生负数。普通 PUSH 不
  做平方根运算；只有系数接近 float 上限时才需要额外范围检查。
- 新增 numeric_contracts：解析可知的对角/旋转/反射/秩一/极小/极大矩阵，

## 内存报告验收（关闭第 3 项）

- peak_bytes 三后端统一为执行阶段相对入口存活量的 CPU 增量峰值，异步 Metal
  分别计量编码和 resolve，取较大值；失败阶段同样记录。录制开销不混入执行峰值。
- context 查询提供预算口径内的当前存活量和单调历史峰值。修复 Soft 早期失败
  重置历史峰值的问题；局部探针不修改全局高水位，亦不跨异步等待保存栈地址。
- device 查询分别提供已知纹理载荷、池保留及池空闲量。后三者不是可相加的总量，
  不含原生缓冲、stencil、驱动开销或驱动保留副本，不宣称实际 VRAM。
  Soft 均为零；GL 原有统计复用相同纹理口径。
- 独立注入分配器验证成功、失败、首个/第二个分配失败的准确增量峰值和历史峰值
  不回退；实际 GL/Metal 验证表面初始字节数及完成后池归还。全量严格 sanitizer
  与 warnings-as-errors 47/47 通过，无 GPU SKIP。


## 执行存储与固定预算验收（关闭第 4 项）

- 命令仅含裁剪路径身份和变换，不持有 CPU 掩码。参考执行器共享 execution
  模块，在 PUSH 时生成祖先几何交集与条件覆盖率，POP 后释放；掩码存活量
  与活动嵌套深度相关，不再随已关闭的兄弟裁剪累计。新后端可选择自己的表示。
- 曲线细分精度和掩码分配失败改由提交执行报告；录制仍同步检查参数、归属和
  引用计数。更新公开契约与几何测试，验证失败目标不变、反复失败无存活量增长。
- 固定 160 KiB 静态池（含 context 与 16 字节粒度碎片），预算 150 KiB。
  48×24 画面包含路径、12 对兄弟双层裁剪及离线 3×5 NEOX 字形，连续 40 帧
  对独立像素参考完全一致；请求峰值 109607 字节，预算峰值 109527 字节。
  执行期 281 个分配失败点逐个验收：目标不变、临时存储回收、同池可继续执行。
- 该证据证明宿主单线程 Soft 的有限池场景，不宣称所有画面都适配此预算，也
  不等于裸机交叉编译/运行证明；动态字体、全屏 float 图层和 GPU 原生内存仍有成本。
- 修复 Metal 紧密裁剪掩码误用 16 字节对齐行距，实际 7×3 表面按行像素验收。
  实际 GL/Metal 完整 48/48、Soft 单线程且 Scene/CAP/Text/Present 全关闭
  10/10 通过，均启用严格 sanitizer 与 warnings-as-errors。

  面积、最大单像素误差，并检查孔洞和实心内部。三个真实后端各 45 个场景。
