# NeoX 图形语义规范 v0（最小子集 · 草案）

> 状态：**草案**。本文件只定义"第一阶段最小子集"（见 §11），并且仅当其中的规则被
> Soft 后端与至少一个 GPU 后端两个实现同时验证后，才允许冻结。
> 本规范是 NeoX 三个契约中的 **SD（语义描述）** 契约；执行表示（ER）为后端私有，
> 捕获格式（CAP）另行定义，均不在本文范围内。

## 1. 范围与符合性

本规范定义 NeoX 绘制结果的**语义**：给定同一份场景描述，任何符合本规范的后端
必须产生何种输出。实现细节（算法、批次、同步）不受本规范约束。

符合性要求：

- 后端无法满足某条语义时，**必须明确失败**（返回 `NEOX_ERROR_UNSUPPORTED`），
  不得静默近似（§10）；
- 两个后端的输出比较按 §9 的容差规则进行；
- 本规范未定义的行为（如退化几何的某些角落）视为**未指定**，后端可自行处理，
  但必须在文档中声明，且同后端两次执行结果必须一致。

## 2. 坐标系与单位

- 绘制目标的坐标原点为**左上角**，+x 向右，+y 向下。
- 坐标单位为**用户单位**（point），与物理像素的映射由平台胶水层负责
  （DPI 缩放不进核心语义）。
- 像素中心位于 `(i + 0.5, j + 0.5)`。
- 几何输入以 float32 表达；实现可使用更高的中间精度，输出须满足 §9 容差。

## 3. 变换

- 变换为二维仿射，记为 `(a, b, c, d, tx, ty)`：
  `x' = a·x + c·y + tx`，`y' = b·x + d·y + ty`。
- 组合顺序：子节点先应用自身变换，再应用祖先变换（自叶向根左乘）。
- 立即模式的状态栈中，新压入的变换与当前变换**左乘复合**（新变换先作用于局部坐标）。
- 组合后矩阵元素必须为有限 float32，线性部分的奇异值平均也须可由 float32
  表达；超出此数值范围的录制操作返回 INVALID_ARGUMENT，不发布命令。
  立即 push、保留场景展开和 CAP 回放采用同一校验，失败保持原帧/捕获不变。
- 退化变换（行列式为零）是合法输入：其下所有几何不产生任何输出，不视为错误。
- 纹理/字形求逆使用 double 中间值，避免有限矩阵因 float 行列式上溢/下溢
  被误判为退化；非零行列式但逆矩阵或变换后角点不能表示为有限 float32 时，
  提交返回 INVALID_ARGUMENT，不发布部分目标内容。矩形端点加法溢出在录制时拒绝。
- 采样逆变换的有限系数不保证 float 中间乘加有限。实现按目标尺寸估计上界，
  必要时将逆矩阵的每一行及对应局部矩形坐标一起乘以二的负整数次幂；纹理
  归一化坐标保持不变，字形在采样前恢复图集像素单位。普通范围不缩放。
  若所需缩放会使非零系数或局部矩形分量进入非正规数范围，提交明确返回
  UNSUPPORTED，保留原目标；不能把算术 NaN 当作矩形内像素继续采样。
- 离屏纹理/字形先与目标范围处理，再转换光栅整数；采样坐标在转整数之前执行
  clamp-to-edge。GPU 可用可见包围盒代替过大的候选四边形，但像素包含与采样
  仍由原变换决定；这可能增加片段工作量，不改变裁剪或混合语义。
- 变换不作用于裁剪矩形/裁剪路径之外的任何状态；不透明度、混合模式不受变换影响。

## 4. 路径几何

### 4.1 路径模型

路径由动词序列与点序列构成。动词：

| 动词 | 点数 | 语义 |
|---|---|---|
| `MOVE` | 1 | 开始新子路径 |
| `LINE` | 1 | 直线段 |
| `QUAD` | 2 | 二次贝塞尔（控制点、终点） |
| `CUBIC` | 3 | 三次贝塞尔（两个控制点、终点） |
| `CLOSE` | 0 | 闭合当前子路径（回到其 `MOVE` 点） |

- 隐式规则：除 `MOVE` 外首个动词之前视为存在 `MOVE(0,0)`；`CLOSE` 之后的
  绘制动词从闭合点继续；连续的 `MOVE` 产生空子路径（无输出）。
- 零长线段、重合控制点为合法输入，不产生输出，不视为错误。
- 隐式起点 `(0,0)` 位于用户空间，须应用当前 CTM；`CLOSE` 后延续的是当前
  子路径的 MOVE 点，不是坐标原点。退化 CTM 下的曲线路径同样为空输出。
- 当前实现用 double 中间值细分曲线，逐一检查控制点到实际输出 float 弦段的
  距离（目标 0.125 设备像素），不会用两个偏移的均值抵消曲率。变换后控制点
  超出有限 float32 返回 INVALID_ARGUMENT；达到 12 层细分仍无法满足距离检查
  返回 UNSUPPORTED，提交保持目标原内容。裁剪只录制几何引用，细分精度与
  执行存储错误在 submission_wait/pump 阶段报告；push 仍同步验证参数和资源归属。
  该距离检查是几何近似的实现约束，不是任意形状像素覆盖率误差的普遍证明。


### 4.2 填充规则

- `NONZERO`：非零环绕数。
- `EVENODD`：奇偶规则。
- 自相交路径按所选规则求环绕数；两种规则的差异是**语义的一部分**，
  后端必须忠实实现，不允许统一退化为某一种。

### 4.3 描边（Phase 2，本版不含）

描边被定义为**几何操作**：输入路径 + 线宽/端帽/连接参数 → 输出可填充轮廓。
核心只消费填充结果。描边展开在 CPU 完成（可离线），不是后端职责。

### 4.4 光栅化与抗锯齿

- 覆盖率 = 像素面积被填充区域覆盖的比例（解析意义，非采样近似）；
  后端可用任意算法逼近，受 §9 容差约束。
- 不允许关闭抗锯齿的"简化模式"作为默认；快速路径可以改变算法，
  不得改变覆盖率定义。

## 5. 颜色

- API 输入颜色为 **sRGB 编码、非预乘** float 四通道。
- 颜色纹理声明编码（`SRGB` / `LINEAR`），过滤和合成使用**预乘线性**值。
  存储可保持原始字节，在采样前转换，不要求上传时展开为浮点数组。
  `RGBA8_DATA` 保存非颜色数据，既不做 sRGB 转换，也不乘 alpha。
- 颜色计算的逻辑表示为**预乘线性**，允许使用 float32 每通道；
  任何中间表示不得量化到 sRGB8——sRGB 量化只发生在最终输出端一次
  （中间量化会破坏 §9 的实心内部逐位一致）。
- A8 遮罩纹理无颜色概念，其采样值作为 alpha，颜色来自绘制时的 paint。
- 混合在**线性光**下进行（上传与输出端做 sRGB↔线性转换）。
  **此为暂定决策**：若 Soft 后端测量表明线性混合使低端目标不可行，
  允许降级为 gamma-naive 混合——但无论选哪条规则，**所有后端必须一致**，
  且最终选择须在本节定稿并删除本条注释。
- NaN/Inf 颜色输入为契约错误，调试构建下断言。

## 6. 混合模式

采用 Porter-Duff 全集 + `PLUS`，共 13 种。记号：`ca/cb` 为源/目标预乘色，
`αa/αb` 为源/目标 alpha；输出 `co = αa·ca·Fa + αb·cb·Fb`，`αo = αa·fa + αb·fb`。

| 模式 | (Fa, Fb) | (fa, fb) |
|---|---|---|
| `CLEAR` | (0, 0) | (0, 0) |
| `SRC` | (1, 0) | (1, 0) |
| `DST` | (0, 1) | (0, 1) |
| `SRC_OVER` | (1, 1−αa) | (1, 1−αa) |
| `DST_OVER` | (1−αb, 1) | (1−αb, 1) |
| `SRC_IN` | (αb, 0) | (αb, 0) |
| `DST_IN` | (0, αa) | (0, αa) |
| `SRC_OUT` | (1−αb, 0) | (1−αb, 0) |
| `DST_OUT` | (0, 1−αa) | (0, 1−αa) |
| `SRC_ATOP` | (αb, 1−αa) | (αb, 1−αa) |
| `DST_ATOP` | (1−αb, αa) | (1−αb, αa) |
| `XOR` | (1−αb, 1−αa) | (1−αb, 1−αa) |
| `PLUS` | (1, 1)，逐通道 clamp 到 [0,1] | (1, 1)，clamp |

默认混合为 `SRC_OVER`。可分混合模式（Multiply/Screen/Overlay 等）属 Phase 2，
加入时须连同 §5 的色彩空间规则一并定义。

### 6.1 覆盖率与混合的关系

覆盖率 `cov ∈ [0,1]` 对**所有**混合模式统一定义为对混合结果的插值：

```
out = cov · blend(src, dst) + (1 − cov) · dst
```

即 `cov` 是"本次绘制在该像素处的参与比例"。推论：CLEAR 在半覆盖像素
表现为 `dst·(1−cov)`（抗锯齿擦除），而非整像素清零；DST 在半覆盖像素
结果恒等于 dst（无视觉变化）。后端不得以"因子不含源"为由对 CLEAR/DST
等模式整像素生效。

对 PLUS，`clamp` 作用于 `blend(src, dst)` **内部**：先逐通道 clamp
`src+dst` 到 [0,1]，再参与覆盖率插值，即 `cov·clamp(src+dst) + (1−cov)·dst`，
结果恒有界。不得先插值再 clamp。

§6.1 只管辖**绘制原语**（路径/纹理/字形）与目标之间的合成。组不透明度与
裁剪（§7）的"参与比例"通过对源的整体调制实现，组合成（临时层→父层）
是全覆盖的 Porter-Duff 混合，不适用 §6.1 的插值形式。

## 7. 合成：组、不透明度、裁剪

- 绘制顺序为**画家算法**：同一容器内按文档顺序，后到者覆盖先到者。
- **组（group）** 是隔离合成边界：组内内容先合成到临时层，再以组的
  不透明度与混合模式整体合成到父层。组不透明度 ≠ 逐子元素不透明度
  （后者会造成子元素重叠处双重透明，二者语义不同，规范明确取前者）。
- **裁剪**为祖先链上所有裁剪区域的交集；裁剪区域是带填充规则的路径
  （矩形是语法特例）。裁剪本身是抗锯齿的（边界覆盖率参与衰减）。
  必须先求区域交集再积分覆盖率，不能直接乘或取最小单独覆盖率。
  相同裁剪重复应用须幂等；像素内不相交的两个区域须得到零覆盖率。
  当前参考执行器对全部活动路径的子扫描线区间求交；隔离层保存相对祖先
  交集覆盖率的条件权重，合成到祖先时不重复衰减同一边界。这仍是 §7
  的像素级隔离合成模型，不宣称解决任意原语相互遮挡的子像素相关性。
- 立即模式的状态栈 push/pop 与保留模式的组节点必须产生**完全相同的语义**；
  这是 §10.2 一致性测试的覆盖对象。

## 8. 位图

- `draw_texture` 语义：源矩形（纹理坐标，float）经采样映射到目标矩形。
- 采样滤波：`NEAREST` / `LINEAR`，逐次绘制指定；边缘行为为 CLAMP。
- 目标矩形经当前变换映射；源矩形**不**变换。
- 上下颠倒的目标矩形（负宽/高）为合法输入，产生镜像。

### 8.0 内容版本

绘制命令固定其录制时的纹理内容，保留场景在 `scene_render` 时固定版本。
同一纹理更新前后的命令可以共存，提交排队或在途不会改变已录制内容。
更新采用按需写时复制；预算不足时返回 OOM，旧版本与已录制命令不变。
释放公开句柄只撤销后续访问，命令和 CAP 持有的内容仍存活至引用结束。
CAP v4 按资源身份与内容版本建立映射，存储紧凑字节或旧版浮点资源；
v1–v3 浮点纹理可回读，不经过重新量化（旧 MSDF 颜色格式限制仍适用）。

### 8.1 文字（NeoX-Text 模块边界）

核心对文字的语义止于 §5 的 A8 遮罩语义：**字形 = 图集纹理中的带位置矩形**，
采样值作为 alpha 与 paint 颜色相乘。以下排版语义属于 NeoX-Text 模块、
不属于本规范，但为避免第二实现的歧义，记录 v0 的明确简化：

- 非法 UTF-8 序列：逐失效字节前进 1（简化版 maximal-subpart 替换）；
- 贪心断行：行首空白丢弃、断行处空白被吞、行尾空白宽度不参与对齐计算；
- 字距（kerning）只在词内计算，跨词边界字距不计；
- 未映射的 codepoint 渲染为字体的 .notdef 字形（glyph 0），不跳过；
- CJK 逐字可断，拉丁按词断行；无复杂文字整形与双向文本（模块文档的
  非目标）。

### 8.2 距离场渲染模式（SDF/MSDF）

`neox_draw_glyphs_ex` 的 `neox_glyph_style.atlas_mode` 扩展字形图集语义：

- **COVERAGE（默认）**：现行 A8 遮罩语义，采样值直接作为 alpha。
- **SDF**：图集为 A8，采样值 `v ∈ [0,255]` 编码有向距离
  `d = (0.5 − v/255) · dist_range_px`（图集像素，正 = 字形内）。
  覆盖率重建：`t = clamp(d·s/w + 0.5, 0, 1); cov = t²(3−2t)`，其中 `s` 为当前变换的
  局部→输出缩放因子，固定为线性部分两奇异值的平均：
  `s = 0.5 * sqrt(a²+b²+c²+d²+2*abs(a*d-b*c))`，`w = softness`
  （输出像素，0 时默认 1）。各向异性下这是方向无关近似，不能保证边缘
  所有法线方向都有正确过渡宽度。完全奇异的变换不绘制。
  若输入已归一化为 `u∈[0,1]`，则 `d=(0.5-u)*dist_range_px`，不再除以 255。
  dist_range 是从编码 0 到 255 的完整距离跨度，不是单侧 padding 半径。
- **MSDF**：图集为 `NEOX_FORMAT_RGBA8_DATA`，RGB 三通道各存一份按边
  着色的距离场，`d` 由 median(r,g,b) 经上式重建。正确的边着色、距离定义
  与误差校正可改善尖角；中位数运算本身不保证尖角正确。alpha 通道忽略。
  内置简化生成器的已知限制与独立测量见 distance-field-quality.md。
- 距离场是**线性数据**：SDF 用 A8（无色彩转换），MSDF 必须 RGBA8_DATA 格式；
  格式与模式不匹配为契约错误。
- **一致性期望**（与 COVERAGE 模式不同，明确放宽）：同后端确定性不变；
  跨后端按 §9——笔画实心内部（cov=0 或 1 的区域）精确一致，边缘过渡区
  覆盖率差 ≤ 32/255 且单调。**不承诺逐位一致**（距离场重建涉及
  smoothstep 等浮点运算，各 GPU 存在 ulp 级差异）。
- `dist_range_px` 须在图集生成与绘制调用两处一致；不匹配属调用方契约
  错误（画面过锐/过钝，不报错的静默语义错误——模块侧应成对管理）。

## 9. 确定性与容差

- 同一后端、同一输入、同一版本：逐位一致。
- 跨后端比较（在 sRGB 空间、每通道 8bit 量化后进行）：
  - 实心内部（距任何边界 ≥ 2px）：**精确一致**；
  - 抗锯齿边界像素：覆盖率差 ≤ 1/8（32/255），且覆盖率沿边界单调；
  - 量化舍入规则：round-to-nearest, ties-to-even。
- 容差值是本规范的一部分；修改容差等于修改规范。
- GL 可在设备创建时显式选择 `NEOX_GL_OUTPUT_GPU`：目标解码和最终输出编码
  在 GPU 上进行，授权相对于 CPU 参考输出的末位量化差异；所有执行报告标记
  `NEOX_EXEC_USED_APPROXIMATION`。此选择不授权更改几何、混合或字形规则。
  默认 `REFERENCE` 不变。当前验收要求 GPU 输出测试所有像素每通道差不超过
  1/255，包含非清屏帧；这不是对任意驱动、任意多帧反馈的普遍误差证明。
  超出验证平台的适配仍需对拍，不得静默把参考路径切为此模式。

> **v0 修订记录（边界容差 2/255 → 32/255）**：第二实现（GPU 三角形批后端）
> 接入时发现原条款不可达成。覆盖率量化粒度由算法决定：Soft 后端水平解析
> × 垂直 8 子扫描线（量化步长 1/8），GPU 超采样盒滤波（如 4×4 网格步长
> 1/16）；不同算法的采样相位与量化误差叠加，最坏情况边界像素差可达
> 3/32 ≈ 24/255，超过原定的 2/255。跨后端一致性因此改为：实心内部精确
> 一致（几何与混合语义的真正验证）+ 边界有界差与单调性（覆盖率定义的验证）。
> 若未来需要给后端真正的覆盖率计算自由度（如 GLES 超采样后端），
> 本条款需升级为"覆盖率容差的可组合模型"；当前两后端共享同一份 CPU
> 覆盖率光栅化（见 ADR 注记），跨后端一致性的实测结果为逐位一致。

## 10. 失败语义与一致性不变量

### 10.1 失败语义

- 默认**保持语义**：无法忠实执行的请求返回 `NEOX_ERROR_UNSUPPORTED`，
  目标内容保持提交前状态（帧提交的失败是原子的，不留半完成画面）。
- 近似执行必须经调用方显式声明（`NEOX_ALLOW_APPROXIMATE`），且实际执行
  路径（含是否发生近似）可在正式构建中通过执行报告查询。

### 10.2 一致性不变量（测试套件的直接依据）

1. 立即式与保留式描述同一内容 → 结果一致（§9 容差）；
2. 增量更新与完整重绘 → 结果一致；
3. 分块渲染与整幅渲染 → 结果一致；

### 设备失效与恢复

设备丢失是 NeoX 已观察到的不可恢复执行故障状态，不是主动硬件健康探测。
后端调用或 pump 发现失效后，`neox_device_is_lost` 保持为真。新帧开始、帧提交
及 GPU 表面操作返回 DEVICE_LOST；已经开始录制的帧仍可取消。CPU 资源管理、
CAP 结束/取消、提交状态/报告查询和释放继续可用。

未执行的排队提交由 pump 取消，不再访问目标；已交给后端的在途提交必须等
后端完成访问后才释放命令和资源。即使后续原生完成事件报告成功，这些尚未
终结的提交仍以 DEVICE_LOST 结束。失效前已完成的提交保留原结果。销毁使用
同一排队取消/在途等待规则。恢复需要新建设备并重建资源；失效 GPU 表面内容
不受失败原子性保证，不能作为恢复来源。

GL 观察 GL_CONTEXT_LOST 与 EGL_CONTEXT_LOST。Metal 对非 OOM 的命令缓冲执行
故障保守地停用该 NeoX 设备，不意味着物理硬件被移除。Metal 命令缓冲 OOM
返回 OUT_OF_MEMORY；普通后端错误与 CPU OOM 不自动停用设备。GL 的普通错误
仍可返回 BACKEND，不能据此推断已经丢失。

检测限于驱动暴露的错误和完成通知；未提供原生重置通知的 CGL 绑定错误仍为
BACKEND。状态查询不能发现尚未观察到的故障，也不提供中断卡死驱动调用的保证。


### 内存统计边界

`neox_context_get_memory_stats` 统计 NeoX 经分配器申请的字节，不包含 context
头部、调用方目标、分配器元数据及原生对象；`memory_budget` 使用同一口径。
共享 context 的调用（包括不同 device 和查询）须由调用方串行化。
`neox_exec_report.peak_bytes` 为执行阶段 CPU 存活量相对阶段入口的最大增量，
异步编码和完成 resolve 分别采样取最大值，失败亦计入；不包含录制阶段，不能
用它直接推导整帧预算。context 历史峰值始终单调不减。
`neox_device_get_memory_stats` 只计算设备当前登记纹理的尺寸乘格式字节数，
池保留量是其中的子集，池空闲量又是池保留量的子集。它不涵盖原生顶点缓冲、
stencil、对齐、驱动开销及驱动仍持有的旧纹理副本，不是物理显存读数，也不
应在统一内存硬件上与 CPU 数字直接相加。Soft 没有原生纹理，三项均返回零。


### 参考执行器的裁剪存储

录制命令保留裁剪路径和变换。当前三个参考执行器在执行时构造活动祖先几何
交集的 float 覆盖率，再转换为相对祖先的条件覆盖率；作用域结束即释放。
这保持重复裁剪幂等，同时避免为整帧每个已关闭裁剪保留全屏掩码。执行器仍
需要全屏浮点图层；固定预算耗尽会使提交失败并保持目标不变，不能据此宣称
任意复杂画面都能在小内存中执行。tests/test_fixed_budget.c 展示不使用系统堆
的有限池分配器、离线字形、路径和嵌套裁剪的具体可运行场景。
